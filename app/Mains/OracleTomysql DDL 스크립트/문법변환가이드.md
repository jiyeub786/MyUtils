## 1. 주요 함수 및 문법 대응표

| 기능 | Oracle | MySQL 8.0+ | 비고 |
| :--- | :--- | :--- | :--- |
| **NULL 처리** | `NVL(expr1, expr2)` | `IFNULL(expr1, expr2)` / `COALESCE(...)` | MySQL에서는 `IFNULL` 사용 권장 |
| **NULL 조건** | `NVL2(expr1, expr2, expr3)` | `IF(expr1 IS NOT NULL, expr2, expr3)` | |
| **현재 시간** | `SYSDATE`, `CURRENT_TIMESTAMP` | `NOW()`, `CURRENT_TIMESTAMP()` | |
| **문자열 연결** | `'A' \|\| 'B'` | `CONCAT('A', 'B')` | `\|\|`는 기본적으로 OR 연산자임 |
| **문자열 자르기** | `SUBSTR(str, pos, len)` | `SUBSTRING(str, pos, len)` / `SUBSTR()` | 동일 사용 가능 |
| **길이 반환** | `LENGTH(str)` (바이트) / `LENGTHB()` | `LENGTH(str)` (바이트), `CHAR_LENGTH(str)` (문자수) | |
| **형변환** | `TO_CHAR(123)` | `CAST(123 AS CHAR)`, `CONVERT(123, CHAR)` | |
| **더미 테이블** | `SELECT 1 FROM DUAL` | `SELECT 1` | `FROM DUAL` 생략 가능 |
| **조건 분기** | `DECODE(col, val1, res1, default)` | `CASE WHEN col = val1 THEN res1 ELSE default END` | `CASE WHEN`으로 통일 |
| **행 번호** | `ROWNUM` | `ROW_NUMBER() OVER()` / `LIMIT` | |
| **Merge 구문** | `MERGE INTO ...` | `INSERT INTO ... ON DUPLICATE KEY UPDATE` | |

## 2. 데이터 타입 변환

| Oracle 타입 | MySQL 대응 타입 | 비고 |
| :--- | :--- | :--- |
| `VARCHAR2(n)` | `VARCHAR(n)` | MySQL은 글자 수(Characters) 기준 |
| `NUMBER(p, s)` | `DECIMAL(p, s)` / `INT` / `BIGINT` | 정수는 `INT`/`BIGINT`, 소수점 포함 시 `DECIMAL` |
| `DATE` | `DATETIME` | Oracle `DATE`는 시간 정보 포함 |
| `TIMESTAMP` | `DATETIME` / `TIMESTAMP` | |
| `CLOB` | `TEXT` / `LONGTEXT` | 64KB 초과 시 `LONGTEXT` |
| `BLOB` | `BLOB` / `LONGBLOB` | |

## 3. 날짜 및 시간 처리

### 날짜 포맷팅 (`TO_CHAR` vs `DATE_FORMAT`)
* **Oracle:** `TO_CHAR(SYSDATE, 'YYYY-MM-DD HH24:MI:SS')`
* **MySQL:** `DATE_FORMAT(NOW(), '%Y-%m-%d %H:%i:%s')`

### 문자열을 날짜로 (`TO_DATE` vs `STR_TO_DATE`)
* **Oracle:** `TO_DATE('2026-08-08', 'YYYY-MM-DD')`
* **MySQL:** `STR_TO_DATE('2026-08-08', '%Y-%m-%d')`

### 날짜 연산
* **Oracle:** `SYSDATE + 7` (일 단위 추가)
* **MySQL:** `DATE_ADD(NOW(), INTERVAL 7 DAY)` / `DATE_SUB(NOW(), INTERVAL 1 MONTH)`

## 4. 조인(Join) 및 서브쿼리 차이

### 아우터 조인 (Outer Join) 기호
* **Oracle (구문법):** 
  ```sql
  SELECT * FROM tableA a, tableB b WHERE a.id = b.id(+)
  ```
* **MySQL (표준 ANSI Join 사용 필수):**
  ```sql
  SELECT * FROM tableA a LEFT JOIN tableB b ON a.id = b.id
  ```

### Inline View (서브쿼리) Alias 필수
MySQL에서는 `FROM` 절에 들어가는 인라인 뷰 서브쿼리에 반드시 별칭(Alias)을 붙여야 합니다.
* **잘못된 예 (MySQL 에러):**
  ```sql
  SELECT * FROM (SELECT id, name FROM users); -- Error: Every derived table must have its own alias
  ```
* **올바른 예:**
  ```sql
  SELECT * FROM (SELECT id, name FROM users) t;
  ```

## 5. 시퀀스(Sequence) 처리

MySQL은 기본적으로 `AUTO_INCREMENT` 속성을 사용합니다. 기존 Oracle Sequence 로직을 대체하는 2가지 방법:

### 방법 A. `AUTO_INCREMENT` 컬럼 적용 (권장)
```sql
CREATE TABLE tst_space_info (
    space_id BIGINT AUTO_INCREMENT PRIMARY KEY,
    space_name VARCHAR(100)
);
```

### 방법 B. Sequence 테이블 생성 및 함수 구현
기존 테이블 구조를 유지해야 하는 경우 Sequence 관리 전용 테이블을 생성하여 관리

## 6. 페이징(Paging) 처리

* **Oracle (기존 ROWNUM 방식):**
  ```sql
  SELECT * FROM (
      SELECT a.*, ROWNUM rnum FROM (
          SELECT * FROM board ORDER BY reg_date DESC
      ) a WHERE ROWNUM <= 20
  ) WHERE rnum > 10;
  ```
* **MySQL (`LIMIT` 절 활용):**
  ```sql
  SELECT * 
    FROM board 
   ORDER BY reg_date DESC 
   LIMIT 10, 10; -- OFFSET 10, FETCH 10 (11번째부터 10건)
  ```

## 7. 인덱스 및 DDL 작성 규칙

### 무중단 인덱스 생성 옵션 (`ALGORITHM`, `LOCK`)
운영 DB에 인덱스 생성 시 테이블 잠금을 방지하기 위해 옵션을 명시합니다.
```sql
CREATE INDEX idx_tst_space_info_ver 
  ON tst_space_info (room_code, ver) 
  ALGORITHM=INPLACE, LOCK=NONE;
```

### 함수 기반 인덱스 (Expression Index)
MySQL 8.0+에서는 함수 기반 인덱스를 생성할 때 표현식을 감싸는 이중 괄호 `(( ... ))`가 필수
  ```sql
  CREATE INDEX idx_stat ON tst_space_info (NVL(sttus, 'n'));
  ```
* **MySQL 8.0+:**
  ```sql
  CREATE INDEX idx_stat ON tst_space_info ((IFNULL(sttus, 'n'))) ALGORITHM=INPLACE, LOCK=NONE;
  ```

## 8. 주의사항 및 트러블슈팅

1. **대소문자 구분 (Case Sensitivity)**
   * Oracle은 테이블명/컬럼명을 기본적으로 대문자로 관리합니다.
   * MySQL은 OS 및 `lower_case_table_names` 설정에 따라 테이블명 대소문자를 구분하므로 **소문자로 통일하여 가이드 준수**를 권장합니다.
2. **빈 문자열 (`''`)과 `NULL` 처리**
   * Oracle: 빈 문자열 `''`을 `NULL`로 인식함.
   * MySQL: 빈 문자열 `''`과 `NULL`을 명확히 구분함.
   * `WHERE col IS NULL` 처리 시 Oracle 데이터를 그대로 이관했을 경우 `col = ''` 조건도 점검해야 함.
3. **`GROUP BY` 절 규격 strict 적용**
   * MySQL 8.0은 `ONLY_FULL_GROUP_BY` 모드가 기본 활성화되어 있어, `SELECT` 절에 있는 컬럼 중 집계함수를 제외한 모든 컬럼이 `GROUP BY` 절에 명시되어야 함.
